# Milestone 5 — בדיקות קבלה והכנה לפרסום

## מטרה
לבדוק את המוצר השלם מול ה-PRD וה-DESIGN, לתקן תקלות שנמצאו, ולהכין גרסת פרסום ל-GitHub Pages לפי ARCHITECTURE 2.7. הפרסום עצמו קורה רק כשהמשתמשת מבקשת „דחוף שינויים לגיטהאב” — ה-push ל-`main` מפעיל את ה-Workflow שמפרסם.

## מצב קיים (מהקוד)
- Vite 8 + TypeScript, בלי Framework. Node מקומי: 24.
- מנוע משחק טהור (`src/game/engine.ts`) עם 11 בדיקות; מודול אחסון (`src/storage/history.ts`) עם 12 בדיקות.
- PWA מוכן (`vite.config.ts`, `src/pwa.ts`): `start_url`/`scope` יחסיים (`./`), כל קובצי ה-Build נשמרים מראש.
- `vite.config.ts` — `base` עדיין ברירת מחדל (`/`), עם הערה שייקבע לפני הפריסה.
- `index.html` מפנה לאייקונים בנתיב מוחלט (`/favicon.ico`, `/icon.svg`, `/apple-touch-icon-180x180.png`). Vite מוסיף להם את ה-`base` בזמן Build — לוודא ב-`dist/index.html`.
- `git remote`: `git@github.com:rotemtarter/simon.git` → כתובת האתר תהיה `https://rotemtarter.github.io/simon/`.
- אין תיקיית `.github/`.

## חלק א — הכנת גרסת הפרסום

### שינוי: `vite.config.ts`
- `base` לפי סוג ההרצה: `'/simon/'` ב-Build (וגם ב-`npm run preview`, שמגיש את ה-Build), `'/'` בשרת הפיתוח — כדי ש-`npm run dev` יישאר בכתובת הרגילה.
  - צורה: `defineConfig(({ command }) => ({ base: command === 'build' ? '/simon/' : '/', ... }))`.
- להסיר את ההערה „will be set before deployment”.

### חדש: `.github/workflows/deploy.yml`
Workflow אחד לפי ARCHITECTURE 2.7:
- טריגר: `push` ל-`main`, וגם `workflow_dispatch` (הפעלה ידנית מתוך GitHub, אם צריך לפרסם שוב בלי שינוי).
- הרשאות מינימליות: `contents: read`, `pages: write`, `id-token: write`.
- `concurrency: pages` (בלי לבטל פריסה שכבר רצה).
- Job `build`: `actions/checkout` ← `actions/setup-node` (Node 22 LTS, `cache: npm`) ← `npm ci` ← `npm test` ← `npm run build` ← `actions/configure-pages` ← `actions/upload-pages-artifact` (תיקייה `dist`).
- Job `deploy` (תלוי ב-`build`): `actions/deploy-pages`, environment `github-pages` עם ה-URL של הפריסה.
- בדיקה שנכשלת או Build שנכשל עוצרים את הפריסה.
- להשתמש בגרסאות העדכניות היציבות של ה-Actions הרשמיים.

### שינוי: `CLAUDE.md` — פקודות הרצה
- כתובת בדיקת PWA/Offline משתנה ל-`http://localhost:4173/simon/`.
- הוספת שורה: **פרסום:** push ל-`main` מפעיל את `.github/workflows/deploy.yml`; כתובת: `https://rotemtarter.github.io/simon/`.

### שינוי: `.claude/launch.json`
אין שינוי בפקודה. אחרי `preview_start` מנווטים ל-`/simon/` (שדה `url` חייב להיות כתובת שורש בלבד).

### ADR-7 ב-`ARCHITECTURE.md`: נתיב פרסום ו-Workflow
- **הקשר:** GitHub Pages של ה-repo `simon` מגיש את האתר תחת `/simon/`.
- **החלטה:** `base: '/simon/'` ב-Build בלבד; Workflow יחיד שבודק, בונה ומפרסם בכל push ל-`main`.
- **השלכות:** בדיקת ה-Build המקומית נמצאת ב-`/simon/`; שינוי שם ה-repo או מעבר לדומיין מותאם מחייב לעדכן את ה-`base`. Service Worker ישן שנרשם בבדיקות מקומיות בכתובת `/` לא משפיע על האתר המפורסם.

### בדיקות שרק המשתמשת יכולה לבצע (אחרי הפרסום, בטלפון)
התקנה אמיתית דורשת HTTPS, ולכן נבדקת רק אחרי ה-push. ברשימה שאמסור בסיום:
- פתיחת `https://rotemtarter.github.io/simon/` בטלפון, התקנה (Android: „התקן אפליקציה”; iPhone ב-Safari: שיתוף ← „הוסף למסך הבית”).
- מצב טיסה ← פתיחת האפליקציה המותקנת ← משחק עם צלילים עד הסוף ← „אודות” מציג את התוצאה.

## חלק ג — תיקונים
- כל תקלה שנמצאת מתוקנת במסגרת ה-Milestone, ונבדקת שוב.
- תיקון שמשנה התנהגות שמתוארת ב-spec — עוצרים ושואלים.

## מה לא נעשה ב-Milestone הזה
- אין commit ואין push בזמן הבנייה. הפרסום מתחיל רק כשהמשתמשת מבקשת „דחוף שינויים לגיטהאב”.
- **לפני הדחיפה הראשונה** המשתמשת מגדירה ב-GitHub (אדריך צעד אחר צעד): ‏repo ‏`simon` ← Settings ← Pages ← Build and deployment ← Source: **GitHub Actions**. בלי זה ה-Workflow ייכשל בשלב הפרסום.
- אין פיצ'רים, מסכים או שירותים חדשים; אין דומיין מותאם.
