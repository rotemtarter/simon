# Milestone 3 — שמירת תוצאות, שיא אישי והיסטוריה

## מטרה
בסיום כל משחק (ניצחון או כישלון) לשמור רשומה ב-`localStorage`, ולהציג את השיא האישי והיסטוריית המשחקים במסך „אודות” ובפס העליון של מסך הבית. אם האחסון אינו זמין — להמשיך לשחק ולהציג הודעה ברורה, בלי לטעון שהתוצאה נשמרה.

## מצב קיים (מהקוד)
- `src/screens/home.ts` — זרימת המשחק. הסיום קורה ב-`press()` כש-`result.outcome` הוא `failed` או `won`. בפס העליון יש placeholder `BEST_SCORE = 0`.
- `src/screens/about.ts` — כרטיס שיא עם placeholder `BEST_SCORE = 0`, ורשימת היסטוריה שמציגה תמיד מצב ריק.
- `src/styles/components.css` — כבר קיימים סגנונות `.best-card`, `.list-card`, `.empty-state`, `.history-row` (ציון | תוצאה | תאריך | שעה | חץ).
- `src/game/engine.ts` — `GameState` כולל `score` ו-`level`; אחרי `failed`/`won` המנוע מתעלם מלחיצות נוספות.
- אייקון `chevron` כבר קיים ב-`src/ui/icons.ts`.

## קבצים

### חדש: `src/storage/history.ts` — מודול האחסון
כל הגישה ל-`localStorage` מרוכזת כאן (ARCHITECTURE 2.2, 2.3). אינו תלוי ב-DOM; מקבל אובייקט `Storage` כפרמטר אופציונלי (ברירת מחדל `window.localStorage`) כדי שאפשר יהיה לבדוק אותו ב-Vitest.

- מפתחות: `simon.gameHistory.v1` (מערך רשומות), `simon.bestScore.v1` (מספר).
- טיפוס:
  ```ts
  interface GameRecord {
    id: string;          // unique local id
    endedAt: string;     // ISO 8601
    score: number;
    finalLevel: number;  // 1..10; 10 on win, level of the mistake on loss
    result: 'won' | 'lost';
  }
  ```
- `loadHistory(storage?)` → `{ ok: true, records: GameRecord[] } | { ok: false }`
  - גישה ל-storage עטופה ב-try/catch (גם עצם הגישה ל-`window.localStorage` יכולה לזרוק).
  - JSON לא תקין או ערך שאינו מערך → נחשב כהיסטוריה ריקה (`ok: true`, רשימה ריקה), בלי לדרוס את הערך הקיים.
  - כל רשומה עוברת בדיקת מבנה (טיפוסים, `result` חוקי, `score` ≥ 0, `finalLevel` בין 1 ל-10, תאריך תקין); רשומות פגומות מסוננות.
  - ממוינת מהחדשה לישנה (לפי `endedAt`).
- `loadBestScore(storage?)` → `number | null` — המקסימום בין הערך התקין ב-`simon.bestScore.v1` לבין הניקוד הגבוה בהיסטוריה; `null` אם האחסון אינו נגיש.
- `saveGame(input: { score, finalLevel, result, endedAt? }, storage?)` → `boolean`
  - קורא את ההיסטוריה התקינה, מוסיף את הרשומה החדשה, כותב חזרה, ומעדכן את `simon.bestScore.v1` רק אם הניקוד החדש גבוה יותר.
  - `id` נוצר מ-`crypto.randomUUID()` כשזמין, אחרת מחותמת זמן + מספר אקראי.
  - כל חריגה (אחסון חסום, `QuotaExceededError`) → מחזיר `false`. מחזיר `true` רק אם הכתיבה של ההיסטוריה הצליחה.
  - אם ערך ההיסטוריה הקיים פגום (JSON לא תקין) — נשמרת היסטוריה חדשה עם הרשומה הנוכחית בלבד (מקרה קצה נדיר; מתועד בהערה).
- אין הגבלת גודל להיסטוריה (ARCHITECTURE 2.3: שומרים הכל בגרסה הראשונה).

### חדש: `src/storage/history.test.ts`
בדיקות Vitest עם `Storage` מזויף (אובייקט בזיכרון) ועם Storage שזורק שגיאות:
- שמירת ניצחון ושמירת כישלון — כל ארבעת השדות נשמרים (ועוד `id`).
- ניקוד חלקי בשלב שלא הושלם נשמר כפי שהתקבל.
- השיא מתעדכן רק כשהניקוד גבוה יותר; `loadBestScore` מחזיר את המקסימום.
- היסטוריה ריקה → רשימה ריקה ושיא 0.
- JSON פגום / רשומות לא תקינות → מסוננות, בלי קריסה.
- Storage שזורק בקריאה → `loadHistory` מחזיר `ok: false`, `loadBestScore` מחזיר `null`.
- Storage שזורק בכתיבה (מכסה מלאה) → `saveGame` מחזיר `false`.
- מיון מהחדשה לישנה.

### שינוי: `src/screens/home.ts`
- הסרת ה-placeholder `BEST_SCORE`; הערך בפס העליון נקרא מ-`loadBestScore()` בעת יצירת המסך. אם `null` (אחסון לא זמין) — מוצג „—”.
- פונקציה `updateBestLink(value)` שמעדכנת את המספר ואת ה-`aria-label`.
- שמירה בסיום משחק: ב-`press()`, מיד כש-`result.outcome` הוא `failed` או `won` (לפני ההשהיה של הצגת המשוב), קריאה אחת ל-`saveGame` עם `state.score`, `state.level` ו-`'won'/'lost'`.
  - מניעת שמירה כפולה: דגל `resultSaved` שמתאפס ב-`start()`; השמירה מתבצעת רק אם הוא `false`.
  - אחרי שמירה מוצלחת — עדכון ערך השיא בפס העליון (מוסתר בזמן משחק, ויוצג עדכני כשחוזרים למסך הבית).
- `showFeedback` מקבל את תוצאת השמירה: אם השמירה נכשלה, במצבי כישלון/ניצחון מתווספת מתחת לניקוד הודעה קצרה: **„לא ניתן לשמור את התוצאה במכשיר זה”**. אם השמירה הצליחה — אין הודעה (המצב הרגיל, כמו ב-Mockups). ההודעה נכללת גם בהכרזה לקורא המסך.

### שינוי: `src/screens/about.ts`
- הסרת ה-placeholder; בעת יצירת המסך: `loadHistory()` ו-`loadBestScore()`.
- כרטיס השיא: הניקוד הגבוה ביותר (0 כשאין רשומות; „—” כשהאחסון אינו זמין).
- רשימת ההיסטוריה (לפי ה-Mockup „אודות / היסטוריה”): שורה `.history-row` לכל רשומה — ניקוד בולט, „ניצחון”/„כישלון”, תאריך `DD.MM.YYYY`, שעה `HH:MM` (שעון מקומי), ואייקון `chevron`.
  - החץ מוצג כקישוט בלבד (`aria-hidden`) ואינו לחיץ — ל-PRD אין מסך פרטי משחק, ואסור להוסיף מסך שלישי.
  - השורה כוללת גם „שלב X” כדי להציג את כל ארבעת הפרטים הנדרשים (PRD 4.א.5: שלב הסיום). מוצג כחלק מטקסט התוצאה, למשל „כישלון · שלב 4”, כדי לשמור על פריסת השורה הקיימת.
  - הרשימה היא `<ol>` עם פריטים; לכל שורה `aria-label` מלא בעברית.
- מצב ריק (קיים): „עדיין אין משחקים שמורים”.
- אחסון לא זמין: במקום הרשימה — הודעה ברורה בסגנון `.empty-state`: **„לא ניתן לגשת להיסטוריה השמורה במכשיר זה”**.
- כל הטקסטים מוכנסים דרך `textContent`/מספרים מעוצבים בלבד (הנתונים מ-`localStorage` לא נכנסים ל-`innerHTML` כטקסט גולמי).

### שינוי: `src/styles/components.css`
- התאמות קטנות בלבד אם נדרש: עמודת התוצאה עם שלב, סגנון רשימה `<ol>` ללא מספור, וסגנון הודעת אי-שמירה במשוב (`.feedback__note`, טקסט קטן בצבע Light Purple/Cool Gray).

## החלטות שכדאי שתדעי עליהן (לא מוגדרות במפורש ב-spec)
1. **החץ בשורות ההיסטוריה** — מופיע ב-Mockup, אבל אין לאן לנווט (שני מסכים בלבד). יוצג כקישוט, לא לחיץ.
2. **השלב בשורת ההיסטוריה** — ה-Mockup מראה רק ניקוד, תוצאה ותאריך, אבל ה-PRD דורש גם שלב סיום. נוסיף אותו בקטן ליד התוצאה.
3. **נוסח ההודעות** כשאין אפשרות לשמור/לקרוא — הנוסחים למעלה מוצעים; אפשר לשנות.
4. **סדר הרשימה** — מהמשחק החדש לישן (כמו ב-Mockup).

## בדיקה בסיום הבנייה
- `npm test` — כל הבדיקות (מנוע + אחסון) עוברות. `npm run build` — ללא שגיאות.
- בדפדפן (`npm run dev`, תצוגת מובייל):
  - „אודות” לפני משחק → מצב ריק, שיא 0.
  - משחק שמסתיים בכישלון בשלב 2–3 → רשומה אחת עם ניקוד כולל לחיצות חלקיות, „כישלון”, שלב נכון, תאריך ושעה.
  - ניצחון (בעזרת קביעת אקראיות קבועה בקונסול/בדיקה, או משחק מלא) → רשומה עם „ניצחון”, שלב 10.
  - השיא בפס העליון ובכרטיס = הגבוה ביותר; רענון הדף משאיר את הנתונים.
  - אין רשומות כפולות לאחר לחיצות מהירות בסיום.
  - הדמיית אחסון חסום (החלפת `localStorage.setItem` שזורק דרך כלי הדפדפן) → המשחק ממשיך, מוצגת הודעת אי-שמירה, ואין רשומה חדשה.
  - נתונים פגומים ב-`simon.gameHistory.v1` → מסך „אודות” לא קורס.
- סגירת שרת הבדיקה בסיום.
