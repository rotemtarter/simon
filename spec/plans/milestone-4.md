# Milestone 4 — PWA ועבודה ללא חיבור

## מטרה
לאפשר התקנה של המשחק כ-PWA, ולאחר טעינה ראשונה — להפעיל אותו ללא אינטרנט: משחק מלא, צלילים, שמירת תוצאות, שיא והיסטוריה. כשאין חיבור — להציג את הודעת המצב „אין חיבור לאינטרנט” (DESIGN מצב 10), וכשמשאב חיוני חסר — להציג הודעה ברורה במקום כשל שקט.

## מצב קיים (מהקוד)
- Vite 8 + TypeScript, בלי Framework. `vite.config.ts` ריק (`base` עדיין ברירת מחדל — ייקבע בפריסה, Milestone 5).
- `index.html` — כבר `lang="he" dir="rtl"`, `theme-color #0F172A`, כותרת „סיימון”. אין manifest, אין אייקונים, אין תיקיית `public/`.
- כל המשאבים כבר מקומיים (ADR-2): גופן Heebo מ-`@fontsource/heebo` (קובצי woff2/woff), שלוש תמונות WebP קטנות ב-`src/assets/` (עד 50KB), אייקונים ב-SVG בקוד.
- צלילים נוצרים ב-Web Audio (`src/game/audio.ts`) — אין קובצי שמע, ולכן הם עובדים Offline מעצמם. אם `AudioContext` לא קיים, המודול שותק בשקט.
- שמירה ב-`localStorage` (`src/storage/history.ts`) — עובדת Offline מעצמה.
- `src/main.ts` — טוען גופן וסגנונות, מצייר רקע ומפעיל את הנתב.

## הגישה
`vite-plugin-pwa` (גרסה 2.x, תומך ב-Vite 8) עם Workbox במצב `generateSW`, כמוגדר ב-ARCHITECTURE. התוסף מייצר את ה-manifest ואת ה-Service Worker בזמן ה-Build, ושומר מראש (precache) את כל קובצי ה-Build. אין Service Worker בשרת הפיתוח (`npm run dev`) — בודקים PWA רק מול ה-Build (`npm run build` + `npm run preview`).

## תלויות חדשות (devDependencies)
- `vite-plugin-pwa` — manifest + Service Worker.
- `@vite-pwa/assets-generator` — יצירת קובצי האייקון בגדלים הנדרשים מקובץ SVG אחד (פעם אחת, הקבצים נשמרים ב-repo).
- `workbox-window` אם התוסף דורש אותו לרישום (נכנס כתלות שלו).

## קבצים

### חדש: `public/icon.svg` — מקור אייקון האפליקציה
אין ב-spec עיצוב מוגדר לאייקון האפליקציה. ההצעה: לוגו לוח 2×2 שמופיע ב-Wireframe של מסך „אודות”, בארבעת צבעי האריחים (כחול, אדום, צהוב, ירוק — אותם ערכים מ-`tokens.css`), עם פינות מעוגלות, על רקע Navy כהה (`#0F172A`) עם נגיעת סגול. ריבועי, עם שוליים בטוחים כך שיתאים גם לגרסת maskable (Android חותך לעיגול/צורה).

### חדשים: קובצי אייקונים ב-`public/` (נוצרים מ-`icon.svg`)
- `pwa-64x64.png`, `pwa-192x192.png`, `pwa-512x512.png`, `maskable-icon-512x512.png`, `apple-touch-icon-180x180.png`, `favicon.ico`.
- נוצרים בפקודה `npx pwa-assets-generator` עם תצורה `pwa-assets.config.ts` (preset `minimal-2023`). הקבצים נשמרים ב-repo; אין צורך להריץ את המחולל בכל Build.

### חדש: `pwa-assets.config.ts`
תצורת המחולל: מקור `public/icon.svg`, preset `minimal-2023`, צבע רקע לגרסת ה-maskable ולאייקון של iOS — `#0F172A`.

### שינוי: `vite.config.ts`
הוספת `VitePWA({...})`:
- `registerType: 'prompt'` בלי חלון עדכון — כלומר בלי `skipWaiting`: גרסה חדשה נכנסת לתוקף רק כשכל חלונות האפליקציה נסגרים ונפתחים מחדש. כך משחק פעיל לעולם לא מתרענן באמצע, ואין ערבוב קבצים מגרסאות שונות (ARCHITECTURE 1.4, 2.2). יתועד כ-ADR.
- `injectRegister: false` — הרישום נעשה ידנית ב-`src/pwa.ts`.
- `manifest`:
  - `name: 'סיימון'`, `short_name: 'סיימון'`, `description` — אותו טקסט כמו ב-`index.html`.
  - `lang: 'he'`, `dir: 'rtl'`.
  - `display: 'standalone'`, `orientation: 'portrait'`.
  - `theme_color: '#0F172A'`, `background_color: '#0F172A'` (מסך הפתיחה של Android כהה, תואם לרקע החלל).
  - `start_url: './'`, `scope: './'` — נתיבים יחסיים, כך שיעבדו גם אחרי שה-`base` ייקבע ל-GitHub Pages.
  - `icons`: 64, 192, 512 ו-512 maskable (`purpose: 'maskable'`).
- `workbox`:
  - `globPatterns: ['**/*.{js,css,html,svg,png,ico,webp,woff2}']` — כל קובצי ה-Build. גופנים: רק `woff2` (כל הדפדפנים המודרניים תומכים; `woff` הוא גיבוי ישן ומכפיל משקל).
  - `navigateFallback: 'index.html'` — פתיחת האפליקציה Offline מגישה את הדף השמור.
  - `cleanupOutdatedCaches: true` — מחיקת מטמון של גרסאות ישנות אחרי עדכון.
  - אין `runtimeCaching` — אין משאבים חיצוניים בזמן ריצה.
- `includeAssets`: `favicon.ico`, `apple-touch-icon-180x180.png`.

### שינוי: `index.html`
- `<link rel="icon" href="/favicon.ico">`, `<link rel="icon" type="image/svg+xml" href="/icon.svg">`, `<link rel="apple-touch-icon" href="/apple-touch-icon-180x180.png">` (ה-manifest עצמו מוזרק אוטומטית ע"י התוסף).
- תגיות iOS: `apple-mobile-web-app-capable` / `mobile-web-app-capable`, `apple-mobile-web-app-title` = „סיימון”, `apple-mobile-web-app-status-bar-style` = `black-translucent` (הרקע הכהה ממשיך מאחורי שורת הסטטוס, כמו ב-Mockups).
- **הודעת גיבוי לטעינה שנכשלה** (משאב חיוני חסר): בתוך `<div id="app">` מוצב מראש טקסט בעברית — „לא ניתן לטעון את המשחק. התחברו לאינטרנט ונסו שוב.” — עם CSS פנימי (inline, כי ייתכן שקובץ ה-CSS הוא שחסר) שמסתיר אותו ומציג אותו רק אחרי השהיה של כ-3 שניות. כשהאפליקציה עולה תקין, הנתב מחליף את תוכן `#app` מיד, וההודעה לא נראית אף פעם. אם ה-JavaScript לא נטען — ההודעה מופיעה במקום מסך כהה ריק. הסגנון: טקסט לבן ממורכז על רקע `#0F172A`, גופן מערכת.

### חדש: `src/pwa.ts` — רישום Service Worker והודעת חיבור
- `registerServiceWorker()`: רישום דרך `virtual:pwa-register` (`registerSW({ immediate: true })`). כשלון ברישום (דפדפן לא תומך, http לא מאובטח) — מתעלמים בשקט; האתר ממשיך לפעול כאתר רגיל (ARCHITECTURE 1.4).
- `watchConnection()`: הודעת „אין חיבור לאינטרנט” (DESIGN מצב 10):
  - מוצגת בעליית האפליקציה אם `navigator.onLine === false`, ובאירוע `offline` של הדפדפן.
  - מוצגת פעם אחת לכל ניתוק — אם השחקן לחץ „המשך”, היא לא תחזור עד שהחיבור יחזור (`online`) וינותק שוב. כשהחיבור חוזר בזמן שההודעה פתוחה — היא נסגרת לבד.
  - **לא קוטעת משחק פעיל:** אם הניתוק קורה באמצע משחק, ההודעה נדחית ותוצג רק כשהמשחק לא פעיל (מסך הבית במצב פתיחה/סיום, או מסך „אודות”). הבדיקה נעשית דרך סימון פשוט ש-`home.ts` מעדכן (`document.body.dataset.playing` או פונקציה מיוצאת — הפשוט מבין השניים בזמן הבנייה).
- תוכן ההודעה (לפי ה-Mockup): שכבה מעל המסך, על רקע החלל, במרכז:
  - אייקון ענן חצוי (`icons.cloudOff`, חדש) בתוך עיגול — כמו סמלי המצב האחרים.
  - כותרת „אין חיבור לאינטרנט”.
  - טקסט „המשחק זמין גם במצב לא מקוון לאחר ההתקנה.”
  - כפתור ראשי „המשך” — סוגר את ההודעה וחוזר למסך שהיה פתוח.
- נגישות: `role="dialog"`, `aria-modal="true"`, `aria-labelledby` לכותרת, הפוקוס עובר לכפתור „המשך” וחוזר למקום הקודם בסגירה.
- ההודעה היא שכבה (overlay) ולא נתיב בנתב — אינה יעד ניווט נוסף (DESIGN, „ניווט כללי”).

### שינוי: `src/main.ts`
קריאה ל-`registerServiceWorker()` ול-`watchConnection()` אחרי הפעלת הנתב.

### שינוי: `src/ui/icons.ts`
הוספת `cloudOff` — ענן בקו 2px מעוגל עם קו אלכסוני חוצה, באותו סגנון של שאר האייקונים.

### שינוי: `src/styles/components.css`
סגנון `.offline-notice` — שכבה במסך מלא (רקע Navy חצי-אטום מעל רקע החלל), תוכן ממורכז, שימוש חוזר בסגנונות הקיימים של `.feedback` (תג עגול עם Glow, כותרת, טקסט) ו-`.btn-primary`. צבע הסמל — Light Purple/לבן כמו ב-Mockup (לא אדום — זו הודעת מידע, לא כישלון).

### שינוי: `src/game/audio.ts` + `src/screens/home.ts` — צלילים לא זמינים
- `unlockAudio()` יחזיר `boolean` — האם יש מנוע שמע זמין (`AudioContext` נוצר בהצלחה).
- אם בלחיצה על „התחל” השמע לא זמין, יוצג מתחת ללוח, פעם אחת למשחק, משפט קצר: **„הצלילים אינם זמינים במכשיר זה”** (`role="status"`). המשחק ממשיך כרגיל עם הדגשה חזותית בלבד. זה המקרה היחיד שבו „משאב חיוני” יכול לחסור אחרי שהאפליקציה כבר עלתה, כי אין קובצי שמע.

### שינוי: `CLAUDE.md` — פקודות הרצה
הוספת שורה: **בדיקת PWA/Offline:** `npm run build && npm run preview` (כתובת: http://localhost:4173). ה-Service Worker פעיל רק בגרסה הזו, לא ב-`npm run dev`.

### שינוי: `spec/ARCHITECTURE.md` — ADRs
- **ADR-5: מדיניות עדכון של ה-Service Worker** — בלי `skipWaiting`; גרסה חדשה נכנסת לתוקף בפתיחה הבאה אחרי סגירה מלאה. מניעת רענון באמצע משחק וערבוב גרסאות; המחיר — עדכון מופיע באיחור של פתיחה אחת.
- **ADR-6: אייקון האפליקציה והודעות זמינות** — לוח 2×2 בצבעי המשחק כאייקון; הודעת Offline כשכבה שאינה קוטעת משחק; הודעת גיבוי סטטית ב-`index.html` למקרה שקובצי האפליקציה לא נטענו.

### `.gitignore`
אין צורך בשינוי (`dist/` כבר מופיע; לא מפעילים Service Worker בשרת הפיתוח, ולכן לא נוצרת תיקיית `dev-dist/`).

## מה לא נעשה ב-Milestone הזה
- אין כפתור „התקן” מותאם או הסבר התקנה בממשק — לא מוגדר ב-PRD/DESIGN. ההתקנה נעשית דרך הדפדפן („הוסף למסך הבית”).
- אין הגדרת `base` ל-GitHub Pages ואין GitHub Actions — שייך לפריסה (Milestone 5). הנתיבים ב-manifest יחסיים כדי שלא יישברו כשה-`base` ישתנה.
- אין הודעת „גרסה חדשה זמינה” — לא מוגדרת ב-spec.

## בדיקות

### אוטומטיות
- `npm test` — כל הבדיקות הקיימות עוברות.
- `npm run build` — עובר, ובתיקיית `dist/` נוצרו `manifest.webmanifest`, `sw.js` וקובצי האייקונים. הפלט של התוסף מציג את רשימת הקבצים השמורים מראש — לוודא שכוללת HTML, JS, CSS, WebP, woff2 ואייקונים.

### בדפדפן (מול `npm run preview`)
1. ה-Service Worker נרשם ופעיל (`navigator.serviceWorker.controller` קיים אחרי רענון).
2. ה-manifest נטען עם כל השדות, וכל האייקונים מחזירים קובץ תקין.
3. המטמון (Cache Storage) מכיל את כל קובצי ה-Build.
4. **Offline אמיתי:** עצירת שרת ה-preview ורענון הדף — האפליקציה נטענת מהמטמון במלואה, כולל גופן ותמונות; אפשר להתחיל משחק, לשחק עד סיום, והתוצאה נשמרת ומופיעה ב„אודות”.
5. הודעת „אין חיבור לאינטרנט”: מופיעה כשהדפדפן מדווח על ניתוק, „המשך” סוגר אותה; ניתוק באמצע משחק לא קוטע אותו וההודעה מופיעה רק אחריו.
6. הודעת הגיבוי: הדמיה של קובץ JS חסר (למשל חסימת בקשה) — מופיעה הודעה בעברית ולא מסך ריק.
7. מסך ריק לא מופיע בשום שלב; אין שגיאות בקונסול.

### ידניות (אצל המשתמשת)
- התקנה בפועל במכשיר נייד דורשת כתובת HTTPS, ולכן תתאפשר במלואה רק אחרי הפריסה ל-GitHub Pages (Milestone 5). עד אז אפשר לבדוק התקנה במחשב, בכרום, מול `http://localhost:4173` (סמל ההתקנה בשורת הכתובת), ואז לנתק את האינטרנט ולפתוח את האפליקציה המותקנת.

## Definition of Done — איך כל תנאי ייבדק
| תנאי | בדיקה |
|---|---|
| אפשר להתקין כ-PWA בסביבה נתמכת | manifest תקין + אייקונים + Service Worker פעיל; התקנה בכרום במחשב מול preview. התקנה בטלפון — אחרי הפריסה. |
| נטען ללא חיבור לאחר טעינה ראשונה | עצירת השרת ורענון — האפליקציה עולה מהמטמון. |
| Offline: התחלה, צלילים, משחק עד סיום, שמירה | משחק מלא כשהשרת עצור; הצלילים נוצרים בקוד ואינם תלויים ברשת. |
| היסטוריה ושיא זמינים Offline | מסך „אודות” כשהשרת עצור מציג את הנתונים. |
| הודעה ברורה כשמשאב חיוני חסר | הודעת הגיבוי ב-`index.html` + הודעת „הצלילים אינם זמינים” + הודעת „אין חיבור לאינטרנט”. |
| אין תלות ב-Backend/שירות חיצוני | אין `runtimeCaching` ואין בקשות לדומיין חיצוני (בדיקה ברשימת בקשות הרשת). |
